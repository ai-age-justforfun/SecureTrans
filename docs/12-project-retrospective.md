## 一、项目是什么

**SecureTrans** — 轻量级跨网文件审批摆渡系统：文件从公司内网（红区/黄区）单向摆渡到外网（绿区），
审批可控、摆渡 0 拷贝、归档可审计。定位中小企业 50~200 人规模，封闭数据中心单服务器部署。

**一句话成果**：从一个想法到生产环境全自动 CI/CD 部署的完整系统，45 个版本、166 次提交、
318 项自动化测试、24 项技术决策（ADR）、800MB 性能验证通过，CD 链路全自动推送生产。

## 四、技术决策回顾（ADR 精选）

| 决策 | 结论 | 理由（一句话） |
|------|------|---------------|
| ADR-001 摆渡机制 | os.rename 0拷贝 | 全平台原生、NAS 兼容、毫秒级，优于软链接/拷贝 |
| ADR-002 Web 框架 | Flask（放弃 FastAPI） | Flask-Login 成熟、团队学习成本低、50 人规模性能非瓶颈 |
| ADR-003 分支策略 | 主干开发 + 单分支 main | 小团队避免合并冲突，Sprint 用文档记录不用目录 |
| ADR-004 运行环境 | Python 3.12 + venv 隔离 | 与系统隔离、离线 wheel cp312 匹配、免源码编译 |
| ADR-005 配置 | 非硬编码，.env 驱动 | 三环境动态部署/运行，地址端口路径必须可配置 |
| ADR-006 安全假设 | 封闭数据中心由基础设施承担网络层安全 | 内/外网均公司内部网络，无攻击威胁，应用层流程管控 |
| ADR-007 发布策略 | 调测期密集发布，RTM 后手工发布，文档-only 不发布 | 版本是产物属性，调测期需要服务器及时验证 |
| ADR-008 端口方案 | 单网卡单端口（当前），PMF 按需升双端口 | 方案 2 增益/成本比最高，封闭内网边际增益趋零 |
| ADR-009 部署凭据 | admin 密码全链路统一（部署重置=测试默认=界面提示） | 消灭第二份默认密码，杜绝"部署后验证失败" |
| ADR-010 配置权威 | 三档矩阵：部署级 .env / 运行时 SQLite / AD 配置 SQLite | 单一权威防漂移，DB 优先，配置总览防遗忘 |
| ADR-011 数据生命周期 | 备份/恢复/出厂重置/模拟数据进系统功能 | 运维功能应收尽收，三环境一套代码配置数据脚本 |
| ADR-012 性能完整性 | 800MB 压力测试 + MD5 四方一致 | 端到端完整性可验证，阈值断言 TDD 可调 |
| ADR-013 AD 集成 | 真实 ldap3 查询 + 精确匹配 + 连接测试 | 消灭 TODO 占位，程序直连 AD 无需入域/SSSD |
| ADR-014 外网下载 | 外网专用详情接口 + health 放行 | 修复"内网可下载外网不能"回归，测试矩阵补齐 |
| ADR-015 治理 | 备份彻底分离 + 特征码受总开关约束 + 外网仅本人 + 审批人闭环 | 用户验收 6+1 组问题的系统性修复 |
| ADR-016 12-Factor | env/ 三模板 + AD_MOCK_MODE + Gitea Actions | 三环境配置数据分层一体化 |
| ADR-017 测试隔离 | 单脚本双入口：verify 全量 / smoke 只读冒烟 + fail-safe 护栏 | 生产误跑全量零副作用 |
| ADR-018 CI 门禁 | 分层流水线 + 计数基线（≥300 / ==10） | 最便宜门禁先失败，防静默删减测试 |
| ADR-019 CI 隔离 | runner 常驻 + 静态检查前置 + 容器化 | 防宿主逃逸、每次 job 干净环境 |
| ADR-020 配置单一来源 | env/*.env 唯一键源 + 键一致性门禁 | CI 与 .env 两路配置信息一致 |
| ADR-021 WSL 稳定性 | 发行版保活 + 单 job 规避 needs bug | 解决 CI 间歇中断/假绿双因 |
| ADR-022 依赖/发布 | 在线优先离线兜底 + 唯一支持矩阵 + 源码/发行包两轨 | 离线数据中心可部署，发布形态业界标准 |
| ADR-023 上传安全 | 文件名 basename 清理 + AD 改密前端拦截 | 修复批量目录上传 500 + 路径穿越 |
| ADR-024 CD 打通 | Release → 容器 job → MD5 校验 → scp → 服务器升级 → 冒烟 | 手工到全自动，AI 辅助开发测试部署闭环 |

## 五、质量保障体系（怎么保证 100%）

```
TDD 全量回归（318 项）
   ├── Windows dev（testing）    python test_api.py        100%
   ├── WSL test（production）    infra/verify.sh           100%
   ├── 容器 CI（隔离）           ci-check 单 job           100%
   └── 生产（只读）              infra/smoke.sh            11/11
秒级静态门禁（fast-check）：语法/静态检查/版本双源/env 键一致/脚本完整
性能与完整性：perf_test.py 800MB 阈值断言 + MD5 四方一致
防缩水：测试计数基线（全量 ≥300 / 冒烟 ==10）
```

**TDD 演进路径**：35 项（首版冒烟）→ 201 项（运维功能化）→ 221 项 → 309/318 项（CICD 门禁）
——每加一个功能必加测试，测试数只增不减，是"PRD 与运行系统一致"的硬保障。

## 六、CICD/GitOps 演进（从手工到全自动）

| 里程碑 | 内容 | 关键排障 |
|--------|------|---------|
| 手工期 | deploy.sh + verify.sh 手工执行 | 部署路径不一致（/mnt/nas vs /opt/securetrans）、异形目录、Python 版本 |
| CI 期 | Gitea Actions + act_runner（WSL） | runner 偶发 shutdown、needs bug 假绿、WSL 空闲终止 |
| CI 容器化 | securetrans-ci:3.12 镜像，每次干净环境 | 网关不可达（固定 docker0）、配置两路漂移（键一致性门禁） |
| CD 期 | Release 发布 → 自动部署生产 | 私钥注入损坏（base64 单行）、资产 URL localhost（sed 替换 host）、token 异常（匿名回退） |
| GitOps | 一次打通，后续发布=push tag | 手动/停止自动触发文档化，act_runner v3.4.2 稳定 |

**沉淀结论**：CI 必须独立容器环境（防逃逸、干净可复现）；CD 密钥走 repo secret 不入仓库；
部署保留 .env/data/nas/venv（生产数据安全）；生产只跑只读冒烟（防污染）。

## 七、踩过的坑与教训（最有价值的部分）

### 7.1 环境一致性（最痛）
- **现象**：本地 WSL 测试通过，生产部署失败（systemd 226/NAMESPACE、异形目录、路径不一致）
- **根因**：三环境路径/配置/依赖不一致，问题只在生产暴露
- **对策**：12-Factor 三环境一体化（ADR-016）、键一致性门禁、统一部署路径、WSL 模拟生产
- **教训**：**本地/测试/生产路径配置必须一致，能本地复现的问题不要带进生产**

### 7.2 测试覆盖盲区
- **现象**：外网无法下载（下载弹窗调管理接口被 403）；特征码关闭仍显示匹配
- **根因**：测试矩阵只测了"接口本身"，没测"前端调用链"；业务规则与 UI 状态未联动
- **对策**：外网面测试清单（自动化+手工 6 项）、特征码受总开关约束
- **教训**：**测试要覆盖真实用户操作链路（前端→API→权限→界面），不只测 API**

### 7.3 配置双份漂移
- **现象**：界面改配置被 .env 覆盖、AD 参数改 .env 不生效
- **根因**：.env 与 SQLite 双份配置，无权威定义
- **对策**：配置权威矩阵（ADR-010）、DB 优先、配置总览页、AD 配置迁 SQLite
- **教训**：**配置必须单一权威 + 可视化总览，杜绝"改了没生效"**

### 7.4 部署凭据不一致
- **现象**：部署后 verify 报"用户名或密码错"反复出现
- **根因**：init_db 播种、deploy 重置、verify 凭据、界面提示各写各的密码
- **对策**：RESET_PASSWORD 唯一源（ADR-009），全链路统一，测试不碰真实密码
- **教训**：**同义字段/凭据必须单一来源，跨脚本跨页面强制统一**

### 7.5 CI 假绿（最隐蔽）
- **现象**：run 显示成功但无测试输出；package 清理阶段误报失败
- **根因**：act_runner needs bug（容器 job 秒退）、WSL 空闲终止、SIGPIPE 误报
- **对策**：单 job 串行、发行版保活、`|| true` 兜底、版本升级 v3.4.2、进程取证
- **教训**：**CI 必须可信——有测试输出才叫通过，不要相信"绿色但没跑"**

### 7.6 文档与代码漂移
- **现象**：发布前大量"文档不一致、代码不一致、测试不一致、环境不一致"
- **对策**：ADR 三文档同步机制、文档-only 变更规则、DEPLOY.md 唯一部署文档
- **教训**：**文档与代码同源演进，发布前做一致性审计（verify + 文档核对）**

## 八、做得好的（保持）

1. **决策有记录**：24 项 ADR 全部三处同步（README/AGENTS/DEPLOY），每次决策有背景/决策/落点

3. **运维功能化**：备份/恢复/重置/模拟数据全部进系统功能（TDD 可调、界面可点）
4. **发布节奏清晰**：文档-only 不发布、代码才发布、RTM 后手工发布——版本含义明确
5. **生产安全**：只读冒烟、部署前备份、不覆盖生产数据、测试不碰真实密码
6. **AI 协同**：AI 负责执行与建议，人负责决策与验收；排障链完整留痕（run 级取证）
