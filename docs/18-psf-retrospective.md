## 二、四维反馈（业界常用：Start / Stop / Continue 变体）

### 2.1 Keep（做得好的，继续）

1. **TDD 全量回归 + 计数基线**：测试只增不减（≥300 门禁），CI 无测试输出=假绿，防静默删减 —— 质量底线守住了
2. **ADR 决策留痕**：从技术选型到部署切换，全部三段式落档，复盘有据可查（50+ 条）
3. **AI 人机协同分工**：AI 给"推荐+理由+代价"，人拍板；变更分级 L1/L2/L3 事件触发，防眩晕
4. **生产只读冒烟**：生产环境绝不写测试数据（smoke.sh 白名单 11 项）—— 数据安全第一
5. **双仓容灾 + 平台隔离**：Gitea 权威 + GitHub 备份 + GitLab 实验线隔离，互不污染
6. **stepping-stone 节奏**：按需调整、技术债显式记账，不追求大公司级完美

### 2.2 Stop（停止/减少，反思）

1. **Stop 无谓的"多想多做"**：部分特性是自己推演的（AD 细节、双网卡复杂化等），未先被使用验证 —— 应遵循"PSF 只做被使用验证的需求"
2. **Stop 文档/代码/测试三方漂移后发布**：曾出现"文档不一致、代码不一致、测试不一致、环境不一致"的低级错误 —— 发布前必须走统一门禁
3. **Stop 环境路径混用**：WSL 用 /mnt/c /mnt/d 导致 CI 十几分钟（切原生路径后分钟级）—— 已记录 ADR-026/043，别再犯

### 2.3 Start（开始，改进方向）

1. **发布前自动化一致性审计**：把"版本号双源一致 + env 键一致 + 文档同步"做成 CI 前置门禁（已有 preflight，扩展覆盖文档）
2. **假设清单显式管理**：docs/13 已建，需每个 Sprint 刷新（证据成立才进 Sprint）
3. **复用方法论模板仓库**：本次沉淀的 AI 人机协同方法论独立成仓，下个项目直接 clone

### 2.4 Longed For（渴望，更大目标）

- 从"AI 辅助开发"进化到"AI 驱动的持续交付"：打 tag 后全自动 CI→Release→CD，人只做发布决策与验收
- 让方法论成为**第二个产品**：不只是 SecureTrans，而是可复用的 AI 时代敏捷工程体系

## 三、关键教训（踩坑 → 根因 → 规则）

| # | 教训 | 根因 | 已固化规则 |
|---|------|------|-----------|
| 1 | 本地/WSL/生产路径不一致导致生产失败 | 三环境路径未统一 | 三环境路径配置一致（ADR-026），能本地复现的问题不带进生产 |
| 2 | CI 假绿（"绿色但没跑"） | 只看状态不看输出 | CI 必须取证（进程/日志/输出）（ADR-018） |
| 3 | .env 与 SQLite 配置双份漂移 | 配置无单一权威 | 部署级 .env / 运行期 SQLite 单一来源（ADR-010） |
| 4 | token 文件误读标签行致 Bad credentials | credential 读取无约定 | 按 token 前缀取真 token 行（ADR-042 补充） |
| 5 | 发布资产通配匹配误选 | 新增同前缀资产后单值假设失效 | 版本号精确提取、资产精确 == 匹配（ADR-041） |
| 6 | WSL 空闲被 Microsoft init 终止 | systemd 非 PID1 | nohup 直跑 + Windows 保活任务（ADR-040） |
| 7 | 蓝绿双实例并发写共享 SQLite | 切换顺序纪律未先定义 | 先停原生再起容器，严禁同时运行（ADR-043） |

## 四、适应（Adapt）——行动项（≤3，可验证）

1. **【Sprint 内落地】发布门禁补全**：preflight 扩展覆盖"文档同步审计（README/AGENTS/DEPLOY ↔ 代码一致）+ 版本号三源一致"，失败即阻断
   - 验证：下一次发布前跑 preflight，0 个不一致告警
2. **【Sprint 内落地】假设清单双周刷新**：docs/13 的每条假设标注"证据状态（成立/证伪/待验证）"，Sprint Review 时更新
   - 验证：每 Sprint Review 产出一条假设状态变更记录
3. **【本月落地】方法论模板独立仓库**：AI 人机协同 Agile 模板（本文档同源方法论）独立 Gitea 仓库，供后续项目 clone 复用
   - 验证：模板仓库已建且 README 可独立指导新项目启动

## 五、假设与技术债刷新

### 5.1 假设状态（节选）

| 假设 | 状态 | 证据 |
|------|------|------|
| 单网卡单地址单端口足够（无需双网卡/双端口） | ✅ 成立 | 生产 10.10.30.8 单网卡跑通 beta（ADR-027/043） |
| Docker 一站式部署优于原生 | ✅ 成立 | 蓝绿验收 + 生产切换成功（ADR-038/043） |
| nginx 暂不需要 | ✅ 成立 | 日均个位数访问，worker 未阻塞（ADR-027，触发条件未到） |
| 双卡/多网段隔离是安全必需 | ❌ 证伪（原型期） | 用户明确"默认没有安全攻击问题"，简化优先 |
| PMF 阶段需要严格合作方管理 | ⏳ 待验证 | 当前信任模式，PMF 再看（PRD 已标假设） |

### 5.2 技术债（显式记账，触发偿还）

| 债 | 触发条件 | 偿还方案 |
|----|---------|---------|
| 后端单文件 app.py（~数千行） | 功能继续膨胀/多人协作 | 按业务域拆分（src/domain/...） |
| nginx 未引入 | worker 阻塞 / 需要对外 HTTPS | 按 ADR-027 触发条件接入 |
| WSL 测试环境与 CI 容器合并 | CI 每次全量重建，性能可接受 | 保持现状，按需再拆 |
| GitHub CD 仅仿真（无法直连封闭数据中心） | 需要真正云端部署 | 维持 CD-SIM + 本地 CD 双轨 |
