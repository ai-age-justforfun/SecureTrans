## 二、各阶段定义与输入输出

### 阶段 1：PSF（Problem-Solution Fit）— 当前阶段

**目标**：确认问题真实存在，且我们的解决方案被用户认可。

| 维度 | 内容 |
|------|------|
| **核心问题** | 用户确实有跨网文件安全外发的痛点吗？我们的审批摆渡方案能解决吗？ |
| **验证方式** | 原型演示 + 用户访谈 + 内部试用 |
| **用户范围** | 3-5 个潜在用户/内部用户体验 |
| **技术深度** | 可工作的原型（前端模拟 + 后端真实API） |
| **周期** | 2-4 周（1-2 个 Sprint） |

**阶段输入**：
- 市场调研结论（跨网文件传输痛点）
- 初始产品假设（审批可控 + 0拷贝摆渡 + 审计可追溯）
- 竞品分析（传统网闸、FTP、邮件等方案的不足）

**阶段输出**：
- ✅ PRD v1.4（产品需求文档，含架构决策）
- ✅ 可交互原型（HTML + Flask后端，88项API测试通过）
- ✅ PSF标准流程文档
- ✅ 测试用例 v1.0（15个场景）
- ✅ 部署包（一键部署到封闭数据中心）
- ✅ 用户验证记录（待收集）
- ✅ PSF迭代小结（本文档系列）

**决策门1：是否进入 PMF？**

| 检查项 | 通过标准 | 当前状态 |
|--------|---------|---------|
| 核心流程跑通 | 提交→审批→摆渡→下载 端到端可用 | ✅ 已完成 |
| 用户认可方案 | 至少3个用户确认"这解决了我的问题" | ⏳ 待验证 |
| 技术方案可行 | os.rename 0拷贝、大文件上传、AD对接路径清晰 | ✅ 已验证 |
| 需求优先级明确 | PMF阶段要做什么已排好序 | ✅ PRD迭代规划已定义 |

> **决策**：全部通过 → 进入PMF；关键项未通过 → 再迭代1个Sprint；方向错误 → 回到问题定义。

---

### 阶段 2：PMF（Product-Market Fit）— 下一阶段准备中

**目标**：确认产品在真实环境中被目标市场持续使用，用户愿意付费/深度依赖。

| 维度 | 内容 |
|------|------|
| **核心问题** | 用户会在真实工作中持续使用吗？愿意为此付费吗？ |
| **验证方式** | 真实部署 + 试点部门使用 + 数据度量 |
| **用户范围** | 1-2个试点部门/客户，10-50人真实使用 |
| **技术深度** | 生产级系统（AD集成、NAS挂载、监控告警） |
| **周期** | 8-12周（4-6个Sprint） |

**阶段输入**：
- PSF阶段输出（PRD、原型、用户反馈）
- 决策门1通过结论
- PMF标准流程文档（已完成 v1.0）
- 试点客户/部门名单

**阶段输出（预期）**：
- 生产级可部署系统（AD集成 + NAS + 监控）
- 部署手册、运维手册、用户手册
- 试点报告（使用数据、用户反馈、PMF结论）
- 度量指标看板（周活跃、留存、审批时效、成功率）
- 决策门2结论

**关键假设与验证指标**（来自PMF流程文档）：

| 假设 | 验证指标 | 成功阈值 |
|------|---------|---------|
| 用户确实需要 | 周活跃用户率 | > 60% |
| 审批流提升效率 | 平均审批时效 | < 24h |
| 0拷贝满足性能 | 摆渡操作耗时 | < 5s |
| 用户愿意持续用 | 4周留存率 | > 50% |
| 管理员能独立运维 | 运维问题工单量 | < 1次/周 |

**决策门2：是否进入规模化？**
- 北极星指标连续4周达标
- 至少1个客户明确表示愿意付费/扩大使用
- 无未解决P0/P1 Bug
- 运维流程跑通

---

### 阶段 3：规模化（Scale）— 未来

**目标**：产品被市场验证，扩大客户范围，实现商业增长。

| 维度 | 内容 |
|------|------|
| **核心问题** | 如何高效获取更多客户？如何支撑更大规模？ |
| **验证方式** | 商业指标（收入、客户数、NPS）+ 技术扩展性验证 |
| **用户范围** | 多客户、多部门、跨地域 |
| **技术深度** | 企业级（PostgreSQL、双机热备、杀毒/DLP、等保） |
| **周期** | 持续 |

**阶段输入**：PMF阶段输出 + 决策门2通过结论

**阶段输出（预期）**：
- 企业级产品（PostgreSQL、高可用、安全合规）
- 商业化体系（定价、销售、客户成功）
- 持续交付流程（CI/CD完善）

## 三、Lean Startup Build-Measure-Learn 循环在各阶段的应用

```
        ┌──────────────────────────────────────────┐
        │            Build（构建）                   │
        │  PSF: 构建原型  PMF: 构建生产系统  Scale: 扩展功能 │
        └──────────────────┬───────────────────────┘
                           │
                           ▼
        ┌──────────────────────────────────────────┐
        │           Measure（度量）                  │
        │  PSF: 用户反馈定性  PMF: 使用数据定量  Scale: 商业指标 │
        └──────────────────┬───────────────────────┘
                           │
                           ▼
        ┌──────────────────────────────────────────┐
        │           Learn（学习决策）                │
        │  PSF: 方案对不对？  PMF: 市场认不认？  Scale: 怎么扩张？ │
        └──────────────────┬───────────────────────┘
                           │
                           ▼
                    调整假设/进入下一阶段
```

**各阶段度量重点差异**：

| 阶段 | 度量方式 | 数据来源 | 决策频率 |
|------|---------|---------|---------|
| PSF | 定性为主（用户访谈、反馈记录） | 访谈笔记、原型体验观察 | 每个Sprint结束 |
| PMF | 定量为主（系统日志、数据库统计） | 系统自动采集 + 定期问卷 | 每周指标review |
| Scale | 商业指标（收入、NPS、 churn） | CRM、财务、客户成功 | 每月/每季度 |
